# 插件全链路测试

## Goal

验证桌面前端网页形态在指定协作后端 `http://106.12.131.38:19006` 上的插件创建到发布完整链路：启动前端、登录测试账号、创建一个可运行插件、确认插件能成功进入团队插件列表，并尝试提交市场发布/审核流程，输出实际结果和发现的问题。

## Requirements

- 前端以网页/Vite 方式运行，连接仓库内置或配置的后端地址 `http://106.12.131.38:19006`。
- 使用用户提供的测试账号登录；账号凭据仅用于本次手工/浏览器验证，不写入任务文档、源码或配置文件。
- 登录、创建插件、上传团队空间、打开/运行插件、提交市场审核等操作必须通过客户端网页完成，不直接调用后端 API 或绕过 UI。
- 例外：如果插件已通过网页提交审核，后续“通过审核/审批”步骤可按用户允许使用后端 API 完成，并在报告中单独标注。
- 创建插件时优先使用低风险、无外部依赖的最小烟雾测试插件，避免消耗模型/第三方服务或引入运行环境依赖。
- 验证插件创建结果：草稿/提交校验、上传接口、团队插件列表刷新、可运行性或可打开性。
- 验证发布链路：若当前账号权限与后端状态允许，提交市场审核/发布；若不允许，记录明确失败原因、接口/页面提示和阻塞点。
- 测试过程不得破坏用户现有数据；创建的测试插件名称/ID 应带有 e2e/smoke 标识，便于后续识别。

## Acceptance Criteria

- [ ] 前端开发服务器成功启动，并确认页面实际使用 `http://106.12.131.38:19006` 作为后端。
- [ ] 测试账号可完成登录，或记录登录失败的可复现错误信息。
- [ ] 仅通过客户端网页成功创建或上传一个测试插件；若失败，记录具体页面步骤、接口响应和前端错误。
- [ ] 新插件可在“团队插件”或等价列表中看到；若不可见，记录刷新/接口/权限问题。
- [ ] 插件运行/打开路径被验证；若无法运行，记录运行时错误和可能归因。
- [ ] 发布/提交市场审核路径被验证；若被权限、审核状态或后端错误阻塞，记录阻塞点。
- [ ] 最终汇总链路结论、截图/控制台/接口证据摘要以及需要修复的问题。
