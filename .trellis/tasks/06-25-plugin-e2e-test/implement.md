# 插件全链路测试 - Implementation Plan

## Execution Checklist

1. 激活 Trellis 任务：按用户约束进入执行，除审核通过步骤外不直接调用后端 API。
2. 启动前端：检查是否已有开发服务器；若无，运行 `pnpm -C apps/desktop vite --host 127.0.0.1 --port 1420`。
3. 打开网页前端并确认后端配置：访问 `http://127.0.0.1:1420`，确认未被本地存储覆盖到其他后端。
4. 登录：使用用户提供的测试账号登录，记录成功/失败结果，不输出密码。
5. 创建插件：使用低风险 client smoke 插件需求，让创建器生成并 stage 草稿；确认右侧预览、结构诊断、提交按钮状态。
6. 提交团队空间：只通过网页按钮提交到团队空间，观察 toast、网络请求和团队插件列表刷新。
7. 运行/打开插件：在团队插件列表中打开测试插件，记录 iframe/runtime 结果。
8. 发布/提交审核：只通过网页操作触发提交市场审核，选择免费价格，记录成功、待审核或权限/后端错误；如需“审核通过”，该审批动作可使用 API。
9. 质量检查：根据是否改代码决定运行 `pnpm -C apps/desktop typecheck`；若仅测试不改代码，可跳过构建并说明。
10. 汇总报告：列出链路状态、阻塞点、可复现步骤和建议修复项。

## Validation Commands

- 前端启动：`pnpm -C apps/desktop vite --host 127.0.0.1 --port 1420`
- 如需静态质量检查：`pnpm -C apps/desktop typecheck`
- 如修改前端构建相关代码：`pnpm -C apps/desktop vite:build`

## Review Gates

- 执行期间：除“通过审核/审批”步骤外，不使用 curl、fetch 脚本或后端接口直接完成登录、创建、上传、运行、提交审核。
- 若发现需要修改源码：暂停并说明问题、修复方案和风险，再进入代码修改。
- 若真实后端返回权限/审核限制：不绕过权限，只记录阻塞点。

## Rollback Points

- 前端启动失败：停止 dev server，记录依赖/端口/环境问题。
- 登录失败：不继续创建，记录认证错误。
- 插件上传成功后发布失败：保留测试插件 ID 和错误信息，等待用户决定是否清理。
