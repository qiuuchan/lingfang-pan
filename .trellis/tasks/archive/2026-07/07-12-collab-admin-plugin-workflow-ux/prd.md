# 优化后台管理端样式与插件审批动线

## Goal

在不改变插件制品仓库核心领域模型的前提下，整理 `apps/collab-admin` 的视觉层级、插件管理加载策略和审核/审批动线，使平台管理员能在更少页面跳转和更少初始请求中完成日常治理操作。

## User Value

- 管理员进入页面后先看到可扫描、可筛选的摘要列表，不被一次性加载的详情数据拖慢。
- 点击具体对象后再在侧边抽屉中加载完整资料、历史和可执行操作。
- 审核、驳回、下架等相关动作集中在同一上下文内，状态、风险和结果清晰可见。
- 后台各页面保持一致的密度、间距、表格、筛选、空状态、错误状态和操作反馈。

## Confirmed Facts

- 管理端位于 `apps/collab-admin`，使用 React、Vite、Tailwind v4、Radix UI 和 Framer Motion。
- `src/App.tsx` 通过 `View` 联合类型切换后台页面，并已对各 view 使用 `React.lazy`；本任务不引入路由框架。
- 插件管理入口为 `plugins-view.tsx`，当前主体是 `plugins/registry-release-review.tsx`。
- 当前审核列表请求 `/api/admin/plugin-releases/review-pending`，打开具体发行版后再请求 `/api/admin/plugin-releases/:id`。
- 当前插件管理实际使用 `/api/admin/plugin-releases`，后端固定最多返回 500 条，并为每条返回完整 `manifest`；搜索和状态筛选完全在前端执行。
- 仪表盘的 `pendingPluginReviews` 仍统计旧 `Plugin.reviewStatus`，与新的 release 级审核模型不一致。
- 市场审核是 release 级审核；每个新版本必须重新审核，通过后才切换市场最新版。
- 团队已发布版本、历史发行版和已购权益不应因市场驳回或下架被物理删除。
- 项目已有 `DetailSheet`、Dialog、Table、Tabs、Pagination、Badge 等通用组件，应优先复用。
- 插件详情允许展示 manifest、能力、文件清单、版本、大小和 SHA，但不得内联加载全部文件内容。

## Requirements

### 1. Management UI Consistency

- 统一后台内容区的页面标题、摘要指标、筛选栏、表格/列表、分页、空状态、加载状态和错误状态。
- 保持管理工具的中等信息密度，减少装饰性卡片、重复说明和多层嵌套容器。
- 桌面端优先支持快速扫描和连续操作；窄屏下不得出现文字覆盖、按钮溢出或不可操作区域。
- 图标按钮使用已有 Lucide 图标和 Tooltip，危险操作使用明确的破坏性样式与二次确认。

### 2. Incremental And On-Demand Loading

- 动态加载是整个后台管理端的数据访问原则，而不只适用于插件页面。
- 用户、团队、插件包、发行版、申请、工单、审计、调用日志、账单记录等可能持续增长的集合必须使用服务端分页、排序、搜索和筛选；前端不得先取固定 200/500 条再做客户端分页。
- 列表接口只返回当前表格需要的轻量摘要字段；详情、关联对象、历史记录、大 JSON、文件清单和统计聚合只在打开对应实体、子 Tab 或功能区时请求。
- 页面或 Tab 未打开时，不得预先请求其业务数据。代码 chunk 的 hover preload 可以保留，但不能因此触发 API。
- 枚举、权限字典和有明确小上限的参考配置可以一次加载；需要在设计中明确其上限和理由。
- “插件发行”Tab 以插件包为列表单位，每个插件包只显示一行摘要，不把所有发行版平铺在首屏。
- 插件审核/管理首页只加载当前筛选条件下的一页包级摘要数据：包名、团队、市场状态、当前市场版本、最新版本和待审核数量；不一次加载所有插件详情、版本、manifest、文件或审核历史。
- 选择某个插件包时，才加载该插件的概览和版本列表；选择具体发行版或进入对应详情 Tab 时，才加载 manifest、文件清单和审核历史。
- 关闭抽屉后保留列表筛选、分页和滚动上下文。
- 详情加载必须有独立 skeleton/loading、error 和 retry 状态，不能阻塞整个列表。
- 详情请求结果应按对象 ID 做当前会话级缓存或避免无意义重复请求；审核动作完成后只失效受影响的列表项和详情。
- 搜索和筛选避免每次击键产生无界请求；采用显式提交或短 debounce，并处理过期响应。
- 切换页面、Tab、筛选或详情对象时，必须取消请求或忽略过期响应，防止旧结果覆盖当前对象。

### 3. Consolidated Plugin Governance Flow

- 将侧栏现有“插件管理”和“审批管理”合并为单一“治理中心”入口。
- 治理中心使用“插件发行”和“团队管理员申请”两个业务 Tab；管理员只看到自己有权限访问的 Tab。
- 插件/发行版及申请详情和主要治理操作放入右侧抽屉，不切换到新的顶级页面。
- 抽屉内集合基本信息、版本/制品摘要、manifest 与能力、文件清单、审核历史和当前可执行动作。
- 通过操作可在风险足够低时直接确认；驳回和下架必须填写原因并使用确认 Dialog，Dialog 不再承载整份详情。
- 操作按钮严格依据权限和 release/listing 状态显示或禁用，提交期间防止重复操作。
- 审核成功后列表、待办数量、抽屉状态和审计结果保持一致。
- 仪表盘待审核数量和快捷入口必须使用新的 release 级审核队列，不能继续读取旧插件表。
- 同一实体只能存在一种主要详情入口；列表行不同时暴露详情、通过、驳回等多组重复按钮。
- 插件“市场当前版”必须按 `currentReleaseId` 精确判断，不能把同一 ACTIVE 包的所有历史版本都标成当前版。
- 已处理的团队管理员申请不得继续显示驳回操作；已下架或非市场当前发行版不得显示会必然返回冲突的下架操作。
- 并发审核必须保证同一待处理对象只能成功完成一次状态转换，不能产生相互矛盾的审核记录。

### 4. Workflow Audit

- 检查插件审核、团队管理员申请、其他已有审批/审核入口是否存在重复页面、重复取数、状态不一致或无返回路径。
- 将同类“列表 + 筛选 + 抽屉详情 + 就地审批”模式尽量收敛为共享组合，而不是新增更多顶级导航。
- 不把领域含义不同的审批强行合成一个后端状态机；界面可以统一，权限和 API 契约仍保持各自边界。

### 5. Compatibility And Scope

- 保持现有 release 级审核、市场最新版切换、下架保留历史和权益等领域语义。
- 优先使用现有 API；只有在列表缺少分页/摘要字段或无法避免过量查询时，才做最小的 `collab-api` / contract 调整。
- 不修改桌面端插件中心、草稿工作区、本地安装器或 `.lfplugin` 格式。
- 不在本任务中重写所有后台业务领域逻辑；深度交互改造聚焦治理中心，但所有无界管理列表都要迁移到服务端分页/按需详情，其他页面通过共享 shell、资源状态和分页模式完成共性优化。
- 设置页改为分组 Tab，并仅在打开相应 Tab 时加载该配置域；仪表盘首屏只加载紧凑核心指标与待办，不预取重型分析区块。

## Acceptance Criteria

- [x] 插件管理首屏只请求一页摘要；未打开行时不请求该发行版详情、文件清单或审核历史。
- [x] 插件首屏按插件包去重，每个包只显示一行；版本历史只在打开对应插件抽屉后加载。
- [x] 点击一项后在右侧抽屉加载并展示完整详情，关闭后列表筛选、分页和位置不丢失。
- [x] 插件列表具备分页、状态筛选、搜索、加载、空、错误和重试状态。
- [x] 侧栏只保留一个“治理中心”入口，内部包含权限可见的“插件发行”和“团队管理员申请”Tab。
- [x] 通过、驳回、下架均在抽屉上下文完成；驳回/下架要求原因并防止重复提交。
- [x] 操作完成后受影响列表项、待办计数和详情状态同步更新，无需整页刷新。
- [x] 仪表盘待审核插件数量来自 `PluginRelease.marketReviewStatus=PENDING`，点击后能进入对应治理队列。
- [x] 不加载插件文件正文；只展示文件元数据和制品摘要。
- [x] 共享后台 shell、筛选栏、表格和详情抽屉的视觉层级一致，桌面和窄屏无明显溢出或遮挡。
- [x] 所有无界后台列表均由服务端分页，浏览器不再先下载固定 200/500 条后客户端分页。
- [x] 未打开的页面、治理 Tab、设置 Tab 和详情子 Tab 不发起其业务 API；打开后才加载，并具备独立加载、错误、空状态和重试。
- [x] 乱序返回的旧请求不会覆盖当前筛选、当前页或当前详情对象。
- [x] 至少检查并记录插件审核及团队管理员申请两条审批动线，确认是否复用统一模式以及保留的领域差异。
- [x] 现有权限、审核状态和市场发布语义不回退。
- [x] 同一对象的并发通过/驳回只能有一个成功，另一个得到明确冲突响应且不会写入矛盾记录。
- [x] 只有 `listing.currentReleaseId` 对应行显示“市场当前版”，下架操作只在当前有效上架对象上出现。
- [x] `pnpm -C apps/collab-admin typecheck` 和 `pnpm -C apps/collab-admin build` 通过；若修改后端，则相关单测、typecheck 和 build 同时通过。

## Out Of Scope

- 修改 `.lfplugin` 制品格式、存储实现、桌面端安装/更新/回滚逻辑。
- 将所有后台审批合并为一个通用数据库实体或统一后端状态机。
- 引入 React Router 或替换现有 UI 技术栈。
- 对未触及的设置、计费或发布模块做大规模重写。

## Product Decisions

- 采用单一“治理中心”导航，使用“插件发行”和“团队管理员申请”两个 Tab 聚合同类工作流。
- UI 模式统一，但插件发行与团队管理员申请继续使用各自权限、API 契约和后端状态机。
- 本轮深度改造治理中心，同时修复共享 Shell、移动侧栏、状态与资源加载模式、仪表盘待办和设置页按 Tab 加载；其他业务页不重写领域逻辑。
- 后台可能增长的数据集合统一采用服务端分页和轻量摘要，实体详情与重型数据统一按需加载。
