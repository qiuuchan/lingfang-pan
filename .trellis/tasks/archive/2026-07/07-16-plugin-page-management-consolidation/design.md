# 插件页面职责与筛选分页设计

## Boundaries

- 主要改动限定在桌面端 `PluginCenterBody`，不改变服务端 API、Tauri IPC 或 contract。
- 草稿页现有上传本地插件、导入为草稿、新建草稿、Agent 编辑及已发布治理能力保持不变，作为职责归位后的唯一管理入口。
- 底层复制草稿、回滚 API 暂不删除，避免影响其他调用方或未来入口。

## UI Responsibilities

- 插件中心：已安装、团队库、插件市场；负责发现、下载/购买安装、运行、详情、版本历史和卸载。
- 已安装列表：运行、详情、卸载；删除导入、复制为草稿和回滚入口。
- 草稿页：上传本地插件、导入草稿、新建草稿、预览/导出、进入 Agent 编辑、发布和删除草稿。
- 已发布页：发行版、市场审核、上架/下架等发布后治理。

## Filtering

- 已安装来源使用安装记录的 `origin`：`builtin | local | team | marketplace`。
- 团队库/插件市场来源使用最新发行版的 `sourceKind`。选项从当前数据动态去重生成，并以现有 `pluginSourceText` 显示人类可读标签，避免硬编码来源说明。
- 每个页签保存独立来源筛选值；数据刷新后若选中来源已不存在，回退到“全部来源”。

## Pagination

- 首版采用客户端分页，沿用当前接口一次性加载数组的行为。
- 每页 10 项，复用 `apps/desktop/src/components/pagination.tsx`。
- 各页签保存独立页码。切换筛选条件时回到第 1 页；筛选或刷新导致总页数减少时，将页码夹紧到有效范围。
- 市场页先按来源过滤，再分页。现有“精选 / 分类热门 / 近期优质”分组会改为当前页的统一插件列表，避免同一个插件因分组重复出现并使分页语义不清。

## Compatibility and Rollback

- 不修改数据契约，因此可与旧后端保持兼容。
- 回滚只需恢复 `PluginCenterBody` 的展示逻辑；安装、卸载、运行与远端目录调用不受影响。
