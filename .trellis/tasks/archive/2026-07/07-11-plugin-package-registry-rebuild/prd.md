# 插件制品仓库与管理系统重构

## Goal

将插件管理重构为“不可变制品来源 -> 下载 -> 本机安装 -> 运行”模型，使团队库、市场、本地安装、内置插件和草稿工作区各自拥有单一且清晰的生命周期。

## Confirmed Facts

- 当前 `Plugin` 行同时保存身份、源码、当前版本、审核和市场状态，更新会覆盖旧制品。
- 当前 `/api/plugins/available` 混合团队、市场和团队安装记录，桌面端又合并内置插件，无法表达当前设备真实安装状态。
- 当前市场安装先写团队级记录再落本机目录，本地写失败或删除后云端与本机状态漂移。
- 当前 `.lfplugin` v3 是 WebView 内 JSZip 生成的 ZIP，支持二进制但包含 `local|draft` 工作流字段，没有统一远端制品协议。
- 当前分支已有统一 `RuntimeResolver`、SHA-256、ZIP 和 SemVer 基础，可作为新包管理器依赖。

## Requirements

- `.lfplugin` v4 ZIP 是唯一上传、下载和导入格式，SHA-256 是唯一制品完整性校验，不实现数字签名。
- 后端分别建模稳定插件包、不可变发行版、市场展示、团队购买权益和逐版本审核；同 package+version 不可覆盖。
- 团队发布允许 SemVer prerelease，市场只允许正式版本；每个市场新版本重新审核。
- 大包进入可切换的 filesystem/S3 制品存储，数据库不再保存完整文件数组。
- 付费市场权益归付款团队；团队插件运行前在线检查当前成员与授权，已购市场插件本地可长期运行。
- 本机原子 JSON 安装账本是设备安装状态唯一事实来源；团队库和市场只提供下载，未安装项不能运行。
- 首期只支持 Windows x64；手动更新，保留上一版用于回滚；依赖在首次运行时准备。
- 卸载默认删除代码、环境和全部插件数据，确认界面必须明确提示；内置插件受保护不可卸载。
- 内置插件通过同一本地安装查询展示；固定和最近使用只持久化 installationId。
- 左侧主导航新增独立“草稿”页面；一条草稿代表一个插件工作区，对话只是编辑历史。
- 草稿目录迁入 `workspaces/<workspaceId>`，不再用 `manifest.draft` 表示生命周期；发布后保留工作区并记录最近发行版。
- 旧客户端必须升级后使用新协议，不长期维护内联大包双写；旧服务数据和本地目录通过幂等迁移保留。
- 正常启动保持确定性；AI 只保留用户主动触发的启动失败诊断/修复，本次不扩展。

## Acceptance Criteria

- [ ] 上传后只保存一个 v4 ZIP 制品、SHA-256 和元数据；重复版本被拒绝。
- [ ] 下载按阶段显示进度，SHA/ZIP/manifest 校验失败时现有安装零变更。
- [ ] “已安装”包含内置、本地、团队和市场来源；团队库/市场未下载项没有运行按钮。
- [ ] 更新先落 pending 版本，首次依赖准备及启动成功后才激活；失败继续运行旧版并可回滚。
- [ ] 卸载确认后删除代码、环境和数据；内置插件无法卸载。
- [ ] 草稿拥有独立左侧导航、搜索/筛选/创建/编辑/预览/发布/导入/导出/删除能力。
- [ ] 草稿发布不删除工作区，同内容/同版本不能重复发布；删除草稿不删除发行版或安装项。
- [ ] 市场购买生成团队权益，新版本逐版本审核；下架不物理删除历史制品和已购权益。
- [ ] 旧后端当前版本可迁移为 v4 release，旧本地目录和 data 可原子迁移或回退。
- [ ] contract、collab-api、Tauri、desktop 和 collab-admin 的类型检查、测试和构建通过。

## Out Of Scope

- 完整 npm registry 协议、Git 直接安装、自动更新、团队强制版本、跨平台制品变体和 AI 自动启动。
- 数字签名、发布者证书链和旧客户端长期兼容。
