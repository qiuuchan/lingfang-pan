# 重构插件创建 Agent 工作区

## Goal

将桌面端“开发插件”页面收口为一个完整、专注的 Agent 工作区：用户在单一主对话流中描述需求、观察 Agent 执行、查看和整理插件产物，并通过精简输入区继续迭代。

本次重构重点解决重复上下文入口、输入区控件过载、会话阅读宽度失控、右侧草稿面板层级过重，以及遗留悬浮创建器造成的双套 UI。

## Requirements

- 保留顶部现有“运行插件 / 开发插件”模式切换，不改变入口与后端 Agent 能力。
- 开发页采用单一 Agent 工作区结构：左侧会话历史、中间唯一对话流、右侧按需出现的插件产物 Inspector。
- “上下文”只保留一个入口，位于 composer 内；移除消息流底部重复的 context/token 栏。
- composer 的默认视觉高度显著降低，核心区只常驻模式、模型、上下文状态和发送/停止；附件、导入、技能、引用插件、提示词优化、语音和工作区操作通过 `+` / 更多菜单访问。
- 历史仅保留在左侧栏；技能不再同时出现在左栏和 composer。
- 助手正文使用连续、易阅读的内容流；思考、工具调用、任务清单继续保持可辨识的结构化状态。
- 右侧区域明确表现为插件产物 Inspector，而非第二个聊天或上下文窗口；信息、文件和检查结果分层展示。
- 创建器 UI 使用应用语义 token，适配亮暗主题，清理本次涉及组件中的硬编码深灰色与过大圆角。
- 删除当前生产未使用的 legacy floating creator 分支及其重复标题栏/历史弹窗，收口为单一页面组件。
- 保留所有既有 Agent 行为：Agent/Plan、模型档位、技能、附件/本地导入、引用插件、工作区刷新/打开、提示词优化、语音、停止、上下文详情、草稿保存与发布。
- 不修改 Agent 循环、插件协议、后端 API、计费与权限规则。

## Acceptance Criteria

- [x] 开发插件页只有一个可见对话滚动区，且没有第二套 creator 标题栏或悬浮窗布局。
- [x] 页面中只有一个“上下文详情”入口；可展示上下文占用与压缩信息，原消息底部 context 栏已移除。
- [x] 空状态和有对话状态下的 composer 均保持紧凑，常驻控件不超过模式、模型、上下文、发送/停止和一个扩展菜单。
- [x] 原有高级功能仍可从 composer 的扩展菜单或对应弹窗访问，没有功能丢失。
- [x] 会话正文最大阅读宽度约 760–840px；在 1024px、1280px、1600px 宽度下无横向溢出或控件重叠。
- [x] 草稿出现后右侧 Inspector 宽度为响应式 360–420px 范围，主对话仍可正常阅读和输入。
- [x] 左侧栏包含新建会话、历史列表和账户入口；技能不在左侧栏重复出现。
- [x] 亮色和暗色主题下，主要文字、边框、表单、状态和按钮均可辨识。
- [x] `pnpm -C apps/desktop typecheck`、`pnpm -C apps/desktop test`、`pnpm -C apps/desktop vite:build` 通过。
- [x] Playwright 覆盖当前页面式 Agent 工作区的空状态、输入态、对话态和草稿 Inspector；旧 floating creator 断言被移除。

## Out Of Scope

- 修改模型调用、工具定义、上下文压缩算法或草稿数据结构。
- 新增后端能力、插件运行时或发布流程。
- 重做整个桌面应用的 TitleBar、主导航或插件运行页。

## Notes

- 用户已明确允许必要重构，并要求直接完善为 Agent 应用。
- 历史决策要求：模型、上下文和导入位于输入区，历史位于 creator 侧栏，开发页不显示外层应用 Sidebar。
