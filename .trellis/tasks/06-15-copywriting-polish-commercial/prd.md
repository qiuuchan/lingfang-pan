# 应用文案商业化打磨（Notion 风专业简洁）

## Goal（目标）

把桌面应用（apps/desktop）+ 管理后台（apps/collab-admin，含官网落地页 landing + 后台 view）的**所有用户可见文案**从「开发者/技术」语感打磨为「商业产品」语感——专业、简洁、自信（Notion/Linear/Figma 中文 UI 风格）。

## 风格准则（Notion 风专业简洁）

### 核心原则
1. **少用「请」**：只在真正需要礼貌请求时用（如「请输入邮箱」→「输入邮箱」或「邮箱」）。命令式更简洁。
2. **少用技术黑话**：用户不感知实现细节。「后端尚未支持」→「暂不支持」；「运行时」→「运行环境」或直接省略。
3. **多用动词 + 结果**：用动作和结果描述，不用状态描述。「上传成功后，团队成员可在插件页运行」→「上传后团队成员可在插件页运行」。
4. **完整但不啰嗦**：必要信息完整，去掉冗余修饰。「密码已重置，下次登录请使用新密码」→「密码已重置」。
5. **统一称呼**：不用「您」（过商务老气），用「你」或省略主语。Notion 风是中性专业，不卑不亢。
6. **状态用短语**：「正在检测…」「正在上传…」用「检测中」「上传中」更简洁。

### 技术→商业 词典（统一映射，所有 agent 遵循）

| 技术词（改前） | 商业词（改后） | 说明 |
|---|---|---|
| 后端尚未支持 / 后端未实现 | 暂不支持 / 即将支持 | 不暴露「后端」内部 |
| 长任务 | 进行中的任务 / 正在处理 | 「长任务」是开发术语 |
| 诊断 | 详情 / 检查结果 | 「诊断」偏技术（除非是健康检查场景） |
| 会话 | 对话 | 「会话」是 session 直译，用户更熟「对话」 |
| session（用户可见处） | 对话 / 会话记录 | 同上 |
| 运行时（runtime） | 运行环境 | runtime 直译生硬 |
| 沙箱 / sandbox | 隔离环境 / 独立环境 | 沙箱是开发术语 |
| 二进制 / binary | 程序 / 可执行文件 | 用户不懂 binary |
| 退出码 | 运行结果 | 退出码是开发术语 |
| 命令 / 命令预览 | 执行命令 / 运行详情 | 必要时保留「命令」但加上下文 |
| probe / 探测 | 检测 | probe 是开发术语 |
| 网关目录 | 模型服务 / API 服务 | 「网关」太技术（但 provider 管理页给 admin 看可保留「服务」） |
| 绑定（binding，用户可见） | 配置 / 关联 | 「绑定」偏技术，用户场景用「配置」 |
| 解密 | 获取 / 读取 | 「解密」暴露实现，用户场景用结果描述 |
| apiKey / api_key（用户可见） | API 密钥 / 密钥 | 英文术语中文化 |
| 脱敏 | 隐藏部分字符 | 脱敏是开发术语 |
| 签名 / 验签（用户可见） | 数字签名 / 完整性校验 | 必要时保留但解释 |
| updater / 更新器 | 检查更新 / 应用更新 | updater 是开发术语 |
| bundle / 打包（用户可见） | 安装包 | bundle 是开发术语 |
| 产物 / asset | 安装包 / 文件 | 产物是开发术语 |
| changelog | 更新日志 | 英文中文化 |
| DRAFT/PUBLISHED/ARCHIVED（用户可见） | 草稿/已发布/已归档 | 英文枚举中文化 |
| STABLE/BETA（用户可见） | 正式版/预览版 | 英文中文化 |
| CLI / 命令行工具 | 命令行工具 / 开发者工具 | CLI 缩写可保留全称 |
| winget（用户可见） | 系统包管理器 / 自动安装 | 必要时解释 |
| 邀请码 redeem | 兑换邀请码 / 加入团队 | redeem 直译 |
| 团队共享 / 云端分享 | 团队共享 / 分享到团队 | 统一用「团队共享」 |
| 提交市场 | 发布到插件市场 | 「提交」→「发布」更主动 |
| 驳回原因 | 未通过原因 | 「驳回」偏审批术语 |

### 保留不动的
- **代码标识符**（变量名、函数名、type、import）完全不动。
- **代码注释**（// 和 /* */）不动（注释是给开发者看的，技术词 OK）。
- **错误码**（如 `binding_not_found`、`gateway_disabled`）不动（这是程序契约）。
- **API 路径**（/api/llm/binding）不动。
- **日志/console 输出**不动。
- **技术性 admin 后台的合理术语**：admin 是给平台管理员（懂技术）用的，某些技术词（如 provider、isActive、签名验签细节）在 admin 可保留，但普通用户可见的文案要商业化。

## Scope（范围）

### 改
- `apps/desktop/src/**/*.tsx` 的用户可见文案（JSX 文本、placeholder、title、label、toast 消息、Dialog 文案、按钮文字）。
- `apps/collab-admin/src/**/*.tsx` 的用户可见文案（landing 官网页 + 后台 view 页）。
- 含 landing/Landing*.tsx、LoginPage、ChangelogPage、DownloadPage、各 *-view.tsx。

### 不改
- 代码注释、import、变量名、类型、错误码、API 路径、console 日志。
- 后端 collab-api（后端文案是 API 响应 message，改了会影响契约，单独任务）。
- packages/contract（契约 schema，不改）。

## Constraints（约束）

- 简体中文（改后仍是简体中文）。UTF-8 无 BOM。
- **语义不变**：打磨的是措辞，不是改功能含义。「请先加入团队」→「请先加入团队」（这种本来就 OK 的不动）或微调为「加入团队后继续」。
- **一致性**：同一概念全应用统一用改后词（如所有「会话」→「对话」）。
- **不引入新功能**：纯文案，不改逻辑/结构/样式。
- 文件操作用专用工具（Edit）。

## Acceptance Criteria

- [ ] AC1 桌面端所有用户可见文案符合 Notion 风（无技术黑话暴露给用户）。
- [ ] AC2 collab-admin landing 官网页文案商业化（面向潜在用户/客户）。
- [ ] AC3 collab-admin 后台 view 文案专业化（admin 可保留必要技术词，但普通可见文案打磨）。
- [ ] AC4 技术词→商业词映射表严格执行（会话→对话、运行时→运行环境等）。
- [ ] AC5 无语义改变（功能不变，仅措辞）。
- [ ] AC6 一致性（同一概念全应用统一）。
- [ ] AC7 typecheck/build 全绿（文案改动不破坏代码）。
- [ ] AC8 无遗漏（grep 残留的技术黑话应为 0 或合理保留）。

## Notes

- 550+ 处文案，用 Workflow 多 agent 分组并行打磨（按页面/模块分）。
- design.md 写执行策略（分组 + 并行 + 一致性校验），不写技术设计（这是文案任务）。
- 每个 agent 拿到统一的「词典 + 风格准则」，保证一致性。
