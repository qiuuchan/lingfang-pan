# ADR-0002：LLM 接入对接第三方网关，平台不自建计费

- **状态**：Accepted
- **日期**：2026-06-09
- **关联**：[LLM 网关对接](../03-backend-and-llm.md)、[产品愿景](../01-vision-and-architecture.md)

---

## 背景

旧版在 LLM 计费上有商业模式级硬伤：

- 代码里有 `billing_policy`、`token_ledger_events`、`platform_share_bps` 等**账本数据结构**，但**没有真实计量**——真实 token 调用是 GenericAgent 用用户自配的 key **直连 OpenCode Go**，平台完全旁路。
- 结果：平台看不到真实用量、控不了价、结不了分成。而北极星宣称的三条现金流全依赖「平台夹在中间计量」——这个中间层被架空了。

产品负责人明确决策：**不自己做计费网关，改用第三方（如 newapi 创建 key 那样的中转站），平台只需要自由对接第三方。**

## 决策

**平台不自建 token 计费/钱包/分成。** LLM 能力通过对接第三方 OpenAI 兼容网关（newapi / one-api 等）供给：

- 租户在第三方网关自行创建 key、设配额、管成本；
- 平台保存「网关绑定」（base_url + 加密 key + 模型清单），通过 `/llm/proxy` 路由插件调用；
- 平台只记录**调用审计**（事实），不记录费用。

## 理由

1. **复杂度外包**：计量/计费/限流是第三方网关已经成熟的能力，平台不重复造。
2. **生态通吃**：OpenAI 兼容协议覆盖 newapi/one-api/LiteLLM/各大中转站，一种协议对接整个生态。
3. **尊重产品决策**：直接落实「用第三方、平台只做对接层」。
4. **安全更简单**：平台只需保管 key + 转发，不碰资金流，合规面小。

## 取舍 / 代价

- **看不到细粒度计费数据**：平台拿不到 per-call 费用。可接受——团队成本在第三方网关侧可见，平台侧审计（谁/何时/哪个插件/什么模型）足够做团队可见性与排错。
- **依赖第三方可用性**：网关挂了 LLM 就不可用。缓解：支持租户配多个绑定；错误显式透传，不伪造结果。
- **放弃了「平台抽成」这条现金流**：与定位 A（先做团队工具、不做变现市场）一致；未来要变现可在订阅层做，而非 token 层。

## 后果

- 领域模型新增 `LlmGatewayBinding`，移除旧版的 token 钱包/账本/分成相关实体。
- `/llm/proxy` 成为唯一 LLM 出口；插件永不持有 key。
- 换供应商/模型对插件透明（统一 OpenAI 兼容协议）。
