# A 部分 · 产品愿景

## 1. 一句话定义

> **LingFang = 一个 no-code 的 AI 插件生成平台**：任何人（包括不会写代码的人）用自然语言描述想要的功能，平台调第三方 LLM API 直接生成可运行的插件，在沙箱里即时预览、对话式迭代，满意后发布——自用、给团队用或分享。

核心是 **「描述 → 生成 → 预览 → 迭代 → 发布」的 AI 造插件闭环**。「使用插件 / 多租户 / 市场」都是围绕这个闭环的支撑。

## 2. 首发杀手场景

用户输入「我要一个把视频脚本拆成分镜表的工具」→ AI 生成插件 → 立刻在沙箱预览能用 → 「再加个标签栏」→ 改好 → 发布给团队。**全程不写一行代码。**

## 3. 北极星指标

> 是否让一个人（哪怕不懂代码）更快地：把脑子里的一个功能想法，描述成一个能跑起来的插件？不是就砍。

## 4. 目标用户

**任何人，以非技术用户为主。** 因此全程 no-code：用户只描述与预览，代码由 AI 全权生成；界面避免技术黑话。

## 5. 核心概念

| 名词 | 定义 |
|---|---|
| **Platform** | 底座：**生成引擎** + 壳 + 租户 + LLM 对接。永不做业务插件。 |
| **Tenant** | 团队/个人空间，归属与隔离单元，无自建钱包/token |
| **User** | 成员，可造插件、用插件 |
| **Plugin** | 沙箱里的功能单元（生成的产物） |
| **PluginDraft** | ★正在生成/迭代的插件草稿——**产品的核心对象** |
| **Capability** | 插件声明的受控能力（看/读文件/联网/调LLM/系统API） |
| **LLM Gateway Binding** | 租户绑定的第三方网关；平台只存 key/路由/审计、不计费。**生成插件和插件运行都经它调 LLM** |

## 6. 非目标

不自研 Agent（生成用直接调 LLM API）· 不自建 token 计费 · 不做官方业务插件 · 首发不做公开市场（先自用/团队）· 首发只桌面（见 §14 开放考量）。

## 7. 后续路线与近期复核

截至 2026-07-04，对近期插件能力看板复核如下：

| 能力点 | 状态 | 依据 / 后续方向 |
|---|---|---|
| 支持使用搜索功能，内置搜索功能并默认开启 | 已完成 | 后端已提供 `/api/search` 与 `/api/search/fetch`，内置公共 SearXNG、Bing HTML 兜底和健康跳过；插件创建 Agent 已接入 WebSearch / WebFetch。 |
| 支持插件调用平台 LLM | 已完成 | `@lingfang/plugin-sdk` 暴露 `sdk.llm.chat` / `sdk.image.generate`，桌面壳通过本地桥转发到平台 relay，插件不持有用户 token 或上游密钥。 |
| 支持创建工作流插件 | 未来更新点 | 当前可以生成“流程型插件”，但尚无正式 workflow 插件类型、步骤编排 manifest、状态恢复与运行记录模型。 |
| 支持跨插件调用 | 未来更新点 | 当前能力清单没有 plugin-to-plugin invoke / event bus / shared contract；后续需补权限声明、调用边界、审计与循环调用防护。 |
| 将聊天记录提到的插件上传到市场 | 未来更新点 | 当前已有草稿上传、市场提交和审核链路，但还缺“从创作聊天记录识别候选插件 → 批量整理 metadata → 一键提交市场”的产品入口与后端编排。 |
| 支持插件版本升级与回滚 | 未来更新点 | 当前插件有版本字段和安装记录，但缺少 semver 升级策略、团队灰度发布、数据迁移说明、失败回滚和变更日志展示。 |
| 支持插件运行日志与错误上报 | 未来更新点 | 当前已有审计与运行桥接基础；后续需要按插件聚合运行日志、异常堆栈、调用耗时、relay 消耗和用户反馈，帮助作者迭代。 |
| 支持插件自动验收与安全扫描 | 未来更新点 | 当前生成期有 manifest / 能力校验；后续可加入静态扫描、依赖风险、权限越界检查、预览冒烟测试和市场上架前自动报告。 |
| 支持团队级插件治理策略 | 未来更新点 | 当前有团队、RBAC、PluginGrant 和审核；后续可做权限模板、风险能力审批流、部门/角色默认安装、禁用策略和审计报表。 |
| 支持 cloud 插件与定时自动化 | 未来更新点 | 当前桌面端负责本地运行与预览；后续可补云端运行时、计划任务、webhook 触发、后台队列和执行结果通知。 |
| 支持插件共享数据与协作状态 | 未来更新点 | 当前有本地 storage.kv 与团队插件安装；后续可提供团队共享 KV / 表格 / 文件空间，让多人在同一插件内协作。 |
| 支持市场推荐与质量分层 | 未来更新点 | 当前市场有搜索、详情、安装、评分评论；后续可加入分类运营、精选合集、质量徽章、兼容性标签和个性化推荐。 |
| 支持付费市场的结算与营销 | 未来更新点 | 当前已有钱包、灵石/余额和市场付费基础；后续可补作者收入看板、提现/结算、优惠券、订阅制和团队采购账单。 |
| 支持 relay 预算与模型策略 | 未来更新点 | 当前 relay 统一计费并区分 fast / premium；后续可加入团队预算、插件级限额、模型白名单、超额提醒和成本归因。 |
| 支持 Web 版插件中心与在线预览 | 未来更新点 | 当前首发形态是 Tauri 桌面；后续可把市场浏览、轻量插件预览、团队安装和审核搬到 Web 端，降低分发门槛。 |

更长期路线：公开市场/分享 → workflow 插件与跨插件编排 → cloud 插件 → 更强的生成与调试（优先复用成熟 agent 框架，不自研底层 agent）。

# B 部分 · 技术架构

## 8. 技术栈

Tauri 2 + Rust 壳（ADR-0001）/ Rust + axum + sqlx + PostgreSQL 后台（ADR-0003）/ 第三方 LLM 网关 OpenAI 兼容（ADR-0002）/ 插件 SDK TypeScript。

## 9. 三支柱（重心 = 生成）

- **壳（Tauri 2）**：描述对话 UI + **沙箱即时预览运行**（生成的插件立刻在 WebView/iframe 跑）+ capability 网关。
- **后台（axum + PG）**：**插件生成服务**（prompt 工程 + 调 LLM + 校验 + 草稿管理）+ 身份/租户/插件归属 + 审计。
- **第三方网关（newapi）**：生成与运行的 LLM 调用都经它，平台不计费。

## 10. ★核心数据流：AI 生成插件

```
用户描述需求
 → 后台构造 prompt（插件 manifest/UI 契约 + 描述 + 当前草稿快照）
 → POST /llm/generate → 第三方 LLM API（structured output 出插件代码）
 → 校验（schema + 安全：禁直连网络/越权能力）→ 不过则把错误回喂、重生成
 → 存 PluginDraft
 → 壳在沙箱即时预览 → 用户继续对话迭代 / 发布
```

铁律：生成用**直接调 API**（非自研 agent）；插件代码由 AI 全权产出（用户 no-code）；key 只在服务端。

## 11. 数据流：插件运行时调 LLM

插件 `sdk.llm.chat` → 壳 capability 网关（校验 manifest + 授权）→ `/llm/proxy` → 第三方网关 → 写审计。插件永不持 key，平台只路由+审计。

> ⚠️ **已迁移至 collab-api**：上述 `/llm/proxy` 出口已不在 Rust apps/server 中，相关 LLM 网关绑定/代理/审计能力已在 commit `7ef4bf0` 迁移到 NestJS **collab-api（`/api/*` 前缀）**。当前实际契约见 [docs/collab-api.md](collab-api.md)，收敛背景见 [docs/collab-platform.md](collab-platform.md)。

## 12. 红线

插件不直连网络 / 不持 key / 跑沙箱 / 三重校验 · 平台不计费只审计 · 服务端默认即连真实 PG（无 demo 默认）· 生成不用自研 agent。

## 13. 里程碑（造插件为核心）

| | 内容 | 本地验证 |
|---|------|---------|
| **M0** | 服务端 + PG + 身份/租户（为草稿归属与保存） | 真实 PG 跑通 注册→建租户→成员 |
| **M1** | **AI 生成引擎**（描述→调 LLM→生成→校验→草稿）+ 壳描述对话 UI | 输入描述，调 newapi 真实生成出合法插件草稿并落库 |
| **M2** | **沙箱即时预览** + 对话式迭代 | 生成的插件在 WebView 跑起来，二次描述能改 |
| **M3** | 发布 + 安装 + 授权（自用/团队） | 草稿 发布→安装→授权→使用 全链路本地跑通 |
| **M4** | 分享 / 公开市场 — 后置 | — |

## 14. 形态决策：Tauri 2 桌面（已定）

面向「任何人」的 no-code 平台，Web 更普惠；但首发**选定 Tauri 2 桌面**——为了**沙箱预览运行**与**客户端插件的系统能力**（截图、本地文件等）。Web 版作为后续触达手段，不在首发。
